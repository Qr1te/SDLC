# ADR-0001: Модульный монолит на Spring Boot и PostgreSQL

- **Статус:** принято
- **Дата:** 2026-11-15
- **Проект:** LinguaLoop, версия 1.0
- **Связанные требования:** REQ-FUNC-001–021, REQ-SEC-001, REQ-REL-002

## Контекст

LinguaLoop — веб-приложение для одного учащегося на учётную запись. Оно управляет курсами, колодами и карточками, планирует повторения по SM-2, ведёт статистику и отправляет напоминания по e-mail. В ЛР3 выбраны Java 21, Spring Boot, Spring MVC, Spring Data JPA, Spring Security, Thymeleaf, PostgreSQL, Flyway, Maven и Docker. Для учебного проекта важны простое развёртывание, транзакционная запись результатов повторения и возможность развивать систему в пределах одной кодовой базы.

## Решение

Использовать модульный монолит на Spring Boot. Разделить код на модули доступа, каталога карточек, планировщика SM-2, целей и статистики, уведомлений и экспорта данных. Контроллеры Spring MVC обслуживают веб-запросы, сервисы содержат правила предметной области, репозитории Spring Data JPA работают с PostgreSQL. Сервер формирует HTML через Thymeleaf. Схема БД изменяется версионируемыми миграциями Flyway.

Запись оценки ответа, журнала повторений и следующего срока карточки выполняется одной транзакцией. SMTP используется только для напоминаний; его недоступность не блокирует занятия и повторения. Приложение собирается Maven и запускается в Docker.

## Рассмотренные варианты

| Вариант | Преимущества | Недостатки |
|---|---|---|
| Модульный монолит Spring Boot | Соответствует стеку ЛР3, просто разрабатывать и развёртывать, транзакции между модулями | Модули требуют дисциплины границ внутри одной кодовой базы |
| Микросервисы | Независимое масштабирование и развёртывание | Сложнее инфраструктура, сеть и согласование данных; не оправдано для учебного масштаба |
| Настольное приложение с локальной БД | Работает без сервера | Не соответствует выбранному веб-формату и внешним ограничениям версии 1.0 |

## Последствия

- Доступ к данным проходит через сервисы и репозитории; контроллеры не содержат SQL и правил SM-2.
- Для окружений разработки и поставки нужны PostgreSQL и SMTP-конфигурация; SMTP допускается отключить.
- Модель данных и миграции должны сохранять историю повторений и расписание карточек.
- Резервный экспорт REQ-FUNC-021 должен переносить не только карточки, но и прогресс, цели и настройки.

## Условия пересмотра

Пересмотреть решение, если появятся требования к независимому масштабированию модулей или к отдельному мобильному клиенту с публичным API.
