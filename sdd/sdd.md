# SDD: BookShelf

| Поле | Значение |
|---|---|
| Версия | 0.3 |
| Статус | Проектный вариант для ЛР4 |
| Основание | SRS 0.2 и запросы CR-001, CR-002 |
| Платформа | Windows 10/11, C#, .NET 10, WPF, SQLite |

## 1. Назначение и границы

BookShelf — настольное приложение личной библиотеки. Пользователь ведёт каталог книг, выполняет поиск, сортирует и фильтрует записи, сохраняет страницу чтения и контролирует прогресс. В версии v0.3 также предусмотрено локальное резервирование и восстановление каталога.

Сводка количества книг по статусам (REQ-FUNC-022) отложена по CR-001. Функция резервирования и восстановления оформлена отдельным REQ-FUNC-023 по CR-002. Облачная синхронизация и объединение библиотек не входят в релиз.

## 2. Архитектурный контекст

Приложение работает локально в Windows. Пользователь взаимодействует с WPF-интерфейсом; основной каталог хранится в SQLite. Сетевой сервис для ежедневной работы не требуется. Файл резервной копии создаётся локально по запросу и переносится пользователем на другой компьютер.

## 3. Компоненты

| Компонент | Ответственность | Требования |
|---|---|---|
| WPF Views | Каталог, карточка книги, поиск, прогресс, диалоги | REQ-FUNC-001–018 |
| ViewModels | Состояние экранов, команды, первичная проверка ввода | REQ-FUNC-001–021 |
| CatalogService | Создание, изменение, удаление и поиск книг | REQ-FUNC-001–013, 019 |
| ProgressService | Проверка страницы, процент и статус чтения | REQ-FUNC-014–018, 021 |
| IBookRepository / SQLite-реализация | Контракт и операции с локальным каталогом | REQ-FUNC-001–005, 019 |
| BackupService | Создание копии, проверка и восстановление | REQ-FUNC-023 |
| Проверка ISBN | Нормализация и обнаружение дублирующей записи | REQ-FUNC-020 |

Представления вызывают команды ViewModel, ViewModel обращается к сервисам, а сервисы используют контракты доступа к данным. UI не выполняет SQL напрямую. BackupService отделён от экранов и логики чтения.

## 4. Данные и правила предметной области

Книга содержит название, автора, жанр, год, ISBN, общее количество страниц и последнюю прочитанную страницу. Процент вычисляется по выражению R = 100 × p / n, где p — текущая страница, n — полный объём.

- p = 0: статус «Не начата».
- 0 < p < n: статус «Читаю».
- p = n: статус «Прочитана».
- p > n: значение не принимается.
- Если новый объём меньше сохранённой страницы, приложение отклоняет изменение и объясняет пользователю причину. Автоматический сброс прогресса не выполняется.

Основной каталог сохраняется в SQLite. Резервная копия должна включать все необходимые для восстановления записи и идентификатор версии формата.

## 5. Резервирование и восстановление

### Создание копии

1. Пользователь выбирает команду и путь назначения.
2. BackupService получает согласованный набор данных.
3. Копия записывается как отдельный файл; незавершённая операция не подменяет предыдущую исправную копию.
4. UI сообщает об успехе либо показывает понятную причину ошибки.

### Восстановление

1. Пользователь выбирает файл копии.
2. Служба проверяет читаемость, структуру и версию формата.
3. До замены каталога приложение запрашивает подтверждение.
4. Данные восстанавливаются целиком.
5. Если проверка или восстановление не проходят, существующая библиотека остаётся доступной.

Слияние каталогов, облачное хранение и автоматическая синхронизация исключены.

## 6. Интерфейсы и взаимодействие

| Интерфейс | Назначение |
|---|---|
| Команды ViewModel | Передача действий пользователя в сервисы |
| IBookRepository | Чтение и изменение локального каталога |
| Контракт резервирования | Запись и чтение копии, проверка формата |
| SQLite | Постоянное хранилище рабочей библиотеки |

Ошибки валидации должны сохранять введённые пользователем значения. Ошибка работы с копией не должна повреждать текущую базу.

## 7. Качество и ограничения

| Показатель из SRS | Целевое значение |
|---|---|
| Поиск по 5 000 книг | До 2 с для 95 % запросов |
| Сортировка, карточка, подтверждение записи | До 1 с |
| Сохранность | Изменения доступны после перезапуска |
| Переход к учёту чтения | Не более трёх действий из каталога |
| Покрытие каталога и прогресса тестами | Не ниже 80 % |
| Поддерживаемые системы | Windows 10 и 11; окно от 1280 × 720 |

Для REQ-FUNC-023 отдельно проверяются повреждённый файл, неизвестная версия, прерывание операции и отказ записи.

## 8. Трассируемость

| Требование | Проектный элемент | Проверка |
|---|---|---|
| REQ-FUNC-001–005, 019 | CatalogService, SQLite-репозиторий | CRUD и повторный запуск |
| REQ-FUNC-006–013 | Служба поиска и параметры выборки | Фильтр, сортировка, результаты |
| REQ-FUNC-014–018, 021 | ProgressService и правила Book | Границы страницы, восстановление позиции |
| REQ-FUNC-020 | Нормализация ISBN | Дубликат, отмена добавления |
| REQ-FUNC-023 | BackupService | Копия, восстановление, ошибочный файл |

## 9. Предположения и риски

Пользователь сам выбирает место копии и переносит её. Формат должен версионироваться. Нехватка места, повреждённый файл или отмена операции не должны портить рабочую базу. Функция считается принятой только после проверки восстановления, а не только факта создания файла.
