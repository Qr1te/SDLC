# Описание проектирования ПО (SDD): LinguaLoop

**Версия:** 0.3 (проектный план ЛР4)  
**Основа:** SRS LinguaLoop v0.2 из ЛР3 и изменение CR-002 / REQ-FUNC-021  
**Стек:** Java 21, Spring Boot, Spring MVC, Spring Data JPA, Spring Security, Thymeleaf, PostgreSQL, Flyway, Maven, Docker

## 1. Назначение и область системы

LinguaLoop — веб-приложение для изучения языков с интервальным повторением. Учащийся создаёт курсы, колоды и карточки, проходит сеансы повторения по SM-2, задаёт дневную цель и отслеживает прогресс. Внешний SMTP-сервер нужен только для e-mail-напоминаний. Версия 1.0 рассчитана на одного учащегося в учётной записи; соревнования, перевод, распознавание речи и офлайн-работа исключены.

Этот документ описывает проектные решения для REQ-FUNC-001–021. REQ-FUNC-021 добавлено изменением ЛР4; его нужно включить в следующую согласованную редакцию SRS.

## 2. Архитектура

Приложение строится как модульный монолит. Браузер отправляет HTTPS-запросы контроллерам Spring MVC; сервер возвращает HTML-страницы Thymeleaf. Контроллеры проверяют форму и вызывают прикладные сервисы. Сервисы применяют правила предметной области и работают с PostgreSQL через репозитории Spring Data JPA. Flyway управляет изменениями схемы.

| Модуль | Ответственность | Требования |
|---|---|---|
| Доступ и профиль | Регистрация, вход, настройки и часовой пояс | F01, F15 |
| Каталог обучения | Курсы, колоды, карточки, поиск, CSV и выделение слов из текста | F02–F06, F13 |
| Повторение | Очередь, SM-2, журнал оценок и трудные карточки | F07, F08, F16 |
| Цели и мотивация | Дневная цель, серия, заморозка, главная страница, предупреждение | F09, F10, F17–F19 |
| Статистика | Показатели, графики и прогноз нагрузки | F11, F12 |
| Уведомления | Озвучивание браузером и e-mail-напоминания | F14, F20 |
| Перенос данных | Полный JSON-экспорт, проверка и транзакционное восстановление | F21 |

Модульные границы — логические пакеты внутри одного приложения, не отдельные сетевые сервисы. Оценки и новое расписание карточки сохраняются в одной транзакции. Сбой SMTP не отменяет результат занятия.

## 3. Основные данные

| Сущность | Основные данные и связи |
|---|---|
| User | Учётные данные в хешированном виде, часовой пояс и настройки |
| Course | Изучаемый язык и уровень; принадлежит User |
| Deck | Название и Course |
| Card | Слово, перевод, транскрипция, пример, теги, состояние и Deck |
| ReviewLog | Дата, оценка, результат SM-2 и Card |
| DailyGoal | Цель и число новых карточек в день для User |
| StreakState | Текущая и наибольшая серии, заморозки и дата последнего выполнения |

Прогресс карточки включает EF, число успешных повторений, текущий интервал и дату следующего повторения. Суммарные показатели строятся по журналу повторений и состояниям карточек.

## 4. Ключевые потоки

### 4.1 Повторение

1. Контроллер запрашивает у сервиса очередь просроченных карточек и новых карточек в пределах лимита.
2. После ответа учащегося сервис валидирует оценку и рассчитывает следующий интервал по SM-2.
3. В одной транзакции сохраняются ReviewLog и новые параметры Card.
4. Сервис целей обновляет прогресс дня и серию; ответ возвращается браузеру.

### 4.2 Создание карточек из текста

Сервис нормализует текст до 5 000 символов, удаляет служебные слова, объединяет повторы и исключает слова, уже известные курсу. Пользователь выбирает кандидатов и вводит переводы. Автоматический перевод не выполняется.

### 4.3 Полный перенос данных (F21)

Экспорт формирует версионируемый JSON без паролей, сессионных токенов и секретов. При импорте сначала проверяются формат, версия, размер, обязательные поля и связи сущностей. После подтверждения данные текущей учётной записи заменяются одной транзакцией. Любая ошибка приводит к откату; существующее состояние не должно быть частично изменено. CSV из F06 переносит только карточки и имеет отдельное назначение.

## 5. Интерфейсы и безопасность

- Веб-интерфейс: HTML-формы и страницы Thymeleaf; целевые сценарии отражены в мокапах ЛР3.
- БД: PostgreSQL через Spring Data JPA; схема обновляется Flyway.
- Почта: SMTP для F14; при недоступности сервера повторение и работа с карточками продолжаются.
- Импорт/экспорт: загрузка и скачивание JSON в пределах аутентифицированной сессии.
- Доступ к объектам ограничивается владельцем User; пароль хранится только в виде bcrypt-хеша, сессии защищаются Spring Security.

## 6. Качество и ограничения

Сохраняются показатели SRS: страницы — до 1,5 с для 95 % запросов; показ следующей карточки и запись оценки — до 300 мс; разбор текста — до 3 с. Журнал и расписание должны согласованно фиксироваться транзакционно. SMTP не является обязательной зависимостью для основных занятий. Изменение схемы БД выполняется версионируемыми миграциями.

Для F21 отдельно проверяются корректный экспорт/импорт, чужая учётная запись, повреждённый файл, неизвестная версия и прерывание транзакции. При round-trip сверяются EF, число успешных ответов, интервал, дата следующего повтора, журнал оценок, дневная цель и серия. После отрицательных сценариев проверяется, что исходные карточки, расписание SM-2 и история повторений не изменились.

## 7. Сборка и развёртывание

Исходный код собирается Maven на Java 21. Приложение и PostgreSQL запускаются контейнерами Docker; секреты SMTP и параметры подключения задаются переменными окружения и не включаются в экспорт или репозиторий. Flyway применяет миграции при старте. Для локальной разработки SMTP может быть отключён.

## 9. Допущения и риски

- Пользователь переносит экспортный файл самостоятельно и хранит его в безопасном месте.
- Первая версия принимает только поддерживаемую версию JSON; автоматическая миграция произвольных старых файлов не выполняется.
- Файл может содержать личный словарь и историю занятий, поэтому интерфейс предупреждает о его содержимом.
- Для подтверждения целостности F21 проверяется не только создание файла, но и восстановление в отдельной тестовой учётной записи.
